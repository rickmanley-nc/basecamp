# Inventory And Asset Tags

Last updated: 2026-08-21

This guide covers the M3 local workflow for inventory entry, location maturity,
asset tags, and maintenance. It uses admin-controlled names and URLs only.

## Quick Inventory Entry

Local setup:

1. Run `pnpm --filter @basecamp/database db:reset`.
2. Run `pnpm --filter @basecamp/server dev`.
3. Run `pnpm --filter @basecamp/web dev`.
4. Open the web app at `http://127.0.0.1:4318`.

Workflow count for the implemented web path:

1. Type or search the item name.
2. Confirm quantity and unit.
3. Confirm or type the location name.
4. Choose category and item type when the defaults are not right.
5. Add optional expiration and notes.
6. Submit once.

The server writes an `inventory_items` row, an `inventory_lots` row, and an
`inventory_events` row. The dashboard then recalculates location maturity and
active quest BOM acquisition needs from current inventory.

## Location Progression

Locations are user-named places such as a house, family house, vehicle, cache,
room, storage shelf, or field location. They progress independently through:

- `known_location`
- `stash`
- `outpost`
- `basecamp`
- `home_base`

Multiple locations can reach `home_base`. A physical `outpost` location is
separate from a gamified category capability outpost, but location readiness can
store a link to the capability outpost that helped validate that place.

## QR Asset Tags

Asset tags use a stable Basecamp asset identifier. The current payload format is:

- Local app/deep-link default: `basecamp://assets/<asset-id>`
- Server URL when configured: `<BASECAMP_PUBLIC_URL>/assets/<asset-id>`

Set `BASECAMP_PUBLIC_URL` before printing tags for a known server or LAN host:

```bash
BASECAMP_PUBLIC_URL="https://basecamp.example" pnpm --filter @basecamp/server dev
```

For LAN-only testing, use an admin-controlled LAN URL, for example:

```bash
BASECAMP_PUBLIC_URL="http://basecamp.local:4317" pnpm --filter @basecamp/server dev
```

The QR SVG is generated by the server from the stored payload. Public issue,
release, and PR text should mention only repo-relative files or admin-controlled
URLs; do not publish local workstation paths.

## Offline And Mobile Status

M3 stores stable tag payloads and exposes the lookup route. M4 adds the shared
mobile QR/barcode scan workflow contract so a Basecamp asset QR payload opens
the matching asset actions and a commercial barcode creates an inventory
confirmation command.

Physical iPhone camera validation remains pending until a signed mobile build
with native scanner screens exists. Real Camera permission, Local Network
permission, offline scan behavior, and reconnect sync must be validated on a
physical iPhone when that build is available.

## Maintenance

Maintenance policies define scope, recurrence interval, and next due date. A
completion event recalculates the next due date. A failure or issue-found outcome
stores a suggested follow-up quest title so later workflow work can convert it
into a real quest.
